Hackathon Implementation Plan  ·  Team of Three

LAGRANGE

An autonomous Operations Research agent that turns a plain-English business question and a raw CSV into an optimal, explained decision.
Built on the Cursor SDK (Python, local runtime) with a deterministic OR tool belt exposed as custom tools. This document is the complete build plan: architecture, the data contract, the exact SDK surface to use, a three-way workstream split, an hour-by-hour schedule with integration gates, the demo script, and the fallback plan for when the venue Wi-Fi dies.
The one thing that wins this Every team will demo a happy path: question in, numbers out. We win on the unhappy path. When a judge adds a constraint that makes the problem impossible, most agents print INFEASIBLE and die. Lagrange diagnoses which business rules conflict, computes the cheapest relaxation, and says: "Your 30 mpg sustainability target and your $2M budget cannot both hold. Drop the target to 26.4 mpg, or raise the budget to $2.31M." That is the moment people remember when they score.

01Strategy: how the scoring actually works

The brief names four judging criteria. They are not equally easy to win. Translation fidelity and business explanation are where every team will land somewhere decent; data ingestion autonomy and resilience & self-correction are where teams either shine or quietly fail. We spend our engineering budget accordingly.

CriterionWhat we build for itWhat the judges seeOwnerEffort
Translation fidelity A typed OptimizationSpec where every constraint carries the exact sentence fragment it came from, plus an explicit unmapped_phrases list for anything the agent could not map. A side-by-side traceability table: business sentence → mathematical equation. Nothing is silently dropped. B C High
Data ingestion autonomy A profile_dataset tool that infers types, units, null strategy, cardinality, and nominates cost / value / category columns with confidence scores. No column names hardcoded anywhere. We drop a CSV the agent has never seen (our wildcard) and it works, live. B High
Resilience & self-correction A repair state machine with four distinct failure branches, backed by elastic-relaxation infeasibility diagnosis rather than blind retries. Judge breaks the model on purpose. Agent explains why in business terms and proposes the minimal fix. A B Highest
Business explanation Shadow prices and binding constraints turned into "what is this rule costing you" sentences, plus a one-screen executive brief. An exec summary a CFO could read, with a "cost of each constraint" table nobody else will have. C Medium

Three rules we do not break

  1. Build the agent, not the answer. The brief says explicitly it is not about solving one problem. Zero column names, zero dataset names, zero problem-specific branches in our code. If we ever type "horsepower" into a source file, we have lost a criterion.
  2. Generality is demonstrated, not claimed. We prepare all three tracks plus a fourth wildcard dataset that we only reveal on stage. Claiming "it generalises" is worth nothing; showing it on unseen data is worth everything.
  3. Feature freeze at T−10h. Hackathons are lost in the last four hours by teams still writing features. After the freeze we only fix, rehearse, and record.
Scope discipline Explicitly out of scope: user accounts, persistence beyond a run folder, multi-user, deployment, model comparison benchmarks, fancy charts beyond two, and any solver we have not already used. Every one of these has killed a hackathon team before.

02Architecture

Five stages. Each stage is one agent.send() on a single durable Cursor SDK agent, so conversation context carries forward, but Python owns the sequencing. We deliberately do not hand orchestration to the model: a scripted pipeline is observable, instrumentable, and reproducible on stage.

STAGE 1
Profile
Inspect the raw CSV. Infer dtypes, units, nulls, cardinality. Nominate candidate cost / value / capacity / category columns.
→ schema_card.json
STAGE 2
Formulate
Map the business question onto the schema card. Choose LP / MIP / assignment. Emit typed spec with rule-to-equation provenance.
→ spec.json
STAGE 3
Compile & Solve
Deterministic spec → OR-Tools model. Solve under a hard time limit. Return status, objective, variable values.
→ solution.json
STAGE 3B
Diagnose & Repair
On error / infeasible / unbounded / timeout: identify the conflicting rules, propose the minimal relaxation, re-solve. Max 3 attempts.
→ diagnosis.json
STAGE 4
Explain
Solution + shadow prices → executive brief. Binding constraints become "what this rule costs you" sentences.
→ brief.md

The central design decision: a typed spec in the middle

The naive build is "agent writes Python, agent runs Python." It demos badly: the model regenerates slightly different code every run, so nothing is reproducible and the failure modes are unbounded. Instead the agent's job is to produce a typed intermediate representation — the OptimizationSpec — and a deterministic Python compiler we own turns that into an OR-Tools model.

What this buys us

  • Reproducible runs, so rehearsal is meaningful.
  • The spec is a renderable artifact — it becomes the traceability table in the UI.
  • Infeasibility diagnosis needs a structured model. You cannot elastically relax free-form code.
  • Failures become typed and repairable instead of arbitrary tracebacks.

What we keep from free-form code

  • The shell tool stays enabled. The agent can still write throwaway pandas to inspect the data.
  • An escape_hatch spec field allows a raw expression when the schema genuinely cannot express something.
  • This matters for the resilience criterion: we are structured by default, not restricted.

03The contract: OptimizationSpec

This is the most important artifact in the project. It is what the agent produces, what the compiler consumes, what the UI renders, and what wins the translation-fidelity criterion.

Interface freeze This schema and the event JSON in orchestrator/events.py are frozen at Gate 1 (H+3). After that, changes require all three people to agree, because everyone is coding against fixtures derived from them. This single rule is what lets three people work in parallel without blocking each other. 
{
  "problem_class": "mixed_integer_linear",        // lp | mixed_integer_linear | assignment | scheduling
  "sense": "maximize",
  "index_sets": {
    "I": { "source": "rows", "filter": "cylinders <= 8", "limit": 400 }
  },
  "parameters": {
    "value":  { "column": "horsepower", "na_strategy": "drop_row", "unit": "hp" },
    "cost":   { "column": "weight", "transform": "x * 9.4", "unit": "usd",
                "derivation": "no price column present; proxied from weight" },
    "effic":  { "column": "mpg", "na_strategy": "median", "unit": "mpg" }
  },
  "variables": [
    { "name": "x", "index": "I", "domain": "integer", "lb": 0, "ub": 12,
      "meaning": "units of vehicle model i to purchase" }
  ],
  "objective": {
    "expr": "sum(value[i] * x[i] for i in I)",
    "business_meaning": "total fleet engine power"
  },
  "constraints": [
    { "id": "budget",
      "expr": "sum(cost[i] * x[i] for i in I) <= 2000000",
      "source_phrase": "a fixed capital budget of two million",   // <-- provenance
      "elastic": false, "priority": "hard" },
    { "id": "fleet_mpg",
      "expr": "sum((effic[i] - 28) * x[i] for i in I) >= 0",
      "source_phrase": "strict corporate sustainability targets",
      "elastic": true, "relax_cost": 1.0, "priority": "soft" }
  ],
  "assumptions": [
    "'sustainability target' interpreted as fleet-average mpg >= 28 (industry default)"
  ],
  "unmapped_phrases": [
    "'prefer European manufacturers' — no manufacturer-region column in this dataset"
  ],
  "clarifying_questions": [
    "Should the mpg target apply to the fleet average or to every vehicle individually?"
  ]
}

Why the four unusual fields matter

FieldWhy it exists
source_phraseEvery equation traces back to the words the user wrote. This renders directly as the traceability table — the single clearest evidence of translation fidelity a judge can be shown.
elastic + relax_costMarks which rules are negotiable. Without this, infeasibility diagnosis has no idea which constraint it is allowed to bend, and the whole differentiator collapses.
unmapped_phrasesHonest reporting of what could not be modelled. Judges trust an agent that admits limits far more than one that silently ignores half the prompt.
derivationWhen no cost column exists, the agent proxies one and says so. This is exactly the "messy reality" the brief describes.
Small feature, large payoff Because source_phrase exists, Owner C can render a two-column table — what you said beside what we solved — in about twenty minutes of work. It will be the screenshot that ends up in the judges' notes.

04The Cursor SDK surface we use

Setup

uv pip install cursor-sdk ortools pandas pyarrow fastapi uvicorn pydantic
export CURSOR_API_KEY="crsr_..."   # Cursor Dashboard -> Integrations

Python, not TypeScript. OR-Tools, pandas and every solver binding live in Python. Putting the orchestrator in the same language as the tool belt means custom tools are ordinary function references rather than a subprocess boundary. Requires Python 3.10+.

Local runtime, not cloud. The datasets sit on disk, the demo must run without depending on venue Wi-Fi for file access, and custom tools are a local-only feature. Pass local= explicitly — the SDK defaults to local when neither local nor cloud is set, and silently getting the wrong runtime is the single most common SDK mistake.

Which SDK features, and why

SDK featureHow we use itWhy it earns its place
Agent.create() + agent.send()One durable agent per business question; each pipeline stage is a separate send().Stage 4 can reference what stage 2 decided without us re-serialising context by hand.
local.custom_toolsThe entire OR tool belt: profile, validate, compile-and-solve, diagnose, sensitivity, scenario.Plain Python functions become agent tools. No MCP server to stand up, no subprocess, no wire format. This is the highest-leverage feature in the whole SDK for us.
tools=[...] / disallowed_tools=[...]Per-stage toolset narrowing: the Formulator gets no shell; the Explainer gets read-only.A stage that cannot reach for the wrong tool cannot wander. Cuts latency and failure surface noticeably.
mode="plan" → SendOptions(mode="agent")Formulation runs in plan mode and surfaces clarifying questions before anything executes.Demonstrates a human-in-the-loop checkpoint for a non-technical stakeholder — directly on-brief.
SendOptions(on_delta=…, on_step=…)Push token deltas and tool-call steps to the UI event bus as they happen.The live "agent thinking" view. Cheap to wire, disproportionately convincing on stage.
run.wait() → RunResultCalled after every stage without exception.The only way to know a stage finished versus errored versus was cancelled. Skipping it also leaks watchers.

Do not use Cloud runtime (custom tools are local-only; needs a cloned repo). Artifacts API (list_artifacts() returns empty on local agents — read the run folder instead). Ambient settings — leave setting_sources unset so nobody's personal ~/.cursor config leaks into a run and makes it irreproducible on a different laptop.

05The tool belt

The agent sees two kinds of tools: Cursor's built-ins, narrowed per stage, and our six custom OR tools. The custom tools are where all determinism lives.

Custom tools (LocalAgentOptions.custom_tools) B owns

ToolSignatureReturns / purpose
profile_dataset(path, sample_rows=2000)Schema card: per-column dtype, null rate, min/max/quantiles, cardinality, inferred unit, and a ranked nomination of which columns look like cost, value, capacity, and category — each with a confidence score. This tool is the data-ingestion-autonomy criterion.
validate_spec(spec)JSON-Schema check plus semantic lint: undefined parameters, index sets referenced but not declared, an objective with no variables, unit mismatch across a comparison, a spec with zero constraints. Returns actionable messages the agent can act on, not a stack trace.
compile_and_solve(spec, time_limit_s=10)Deterministic spec → OR-Tools model → solve. Normalised status (OPTIMAL, FEASIBLE, INFEASIBLE, UNBOUNDED, TIMEOUT, COMPILE_ERROR), objective value, non-zero variable assignments, MIP gap, wall time. Always returns the best incumbent on timeout.
diagnose_infeasibility(spec)Adds a non-negative slack to every elastic constraint, minimises the weighted sum of slacks, and reports the minimal set of rules that must bend and by exactly how much. This tool is the resilience criterion.
sensitivity_report(spec, solution)Shadow prices and binding constraints from the LP relaxation, plus reduced costs for near-miss items. Feeds the "what each rule costs you" section of the brief.
run_scenario(spec, overrides)Re-solve with patched numbers. Powers live judge Q&A and the tornado chart.

Built-in Cursor tools, per stage A owns

StageBuilt-ins offeredRationale
1 · Profileread, ls, glob, shellShell stays on so the agent can run ad-hoc pandas when the profiler's nominations look wrong. Genuine ingestion autonomy.
2 · Formulateread, grep  ·  disallowed_tools=["shell","edit"]Formulation is a reasoning task. Denying execution stops the agent from "just writing a script" and bypassing the spec.
3 · Solve / repairread, write, edit, shellFull latitude for the escape hatch and for inspecting solver output.
4 · Explainread, writeWriting prose. Nothing else needed.
Custom tools or an MCP server? Use custom_tools for the hackathon: a Python function reference, zero transport, and edits take effect on the next run. If you also want the tool belt usable from the Cursor IDE while developing (genuinely handy for Owner B), wrap the same functions in a small stdio MCP server later and pass it via mcp_servers={"orcore": StdioMcpServerConfig(command="python", args=["-m","orcore.mcp"])}. Write the functions once, expose them twice. Do not do this before Gate 3.

06The self-correction loop

Blind retry is what everyone else will build, and it fails visibly on stage. We branch on the kind of failure, because each kind has a different correct response.

StatusDiagnosis stepRepair actionMax
COMPILE_ERRORReturn the validate_spec message plus the offending JSON path.Agent patches only that field and revalidates. No full regeneration.3
INFEASIBLEdiagnose_infeasibility → minimal conflicting rule set with required slack per rule.Two options presented: relax the named soft rule by the computed amount, or report the conflict to the user with the numbers. Never silently relax a rule marked hard.2
UNBOUNDEDFind variables with no upper bound appearing in the objective with a favourable sign.Infer a bound from the data (e.g. available stock, budget ÷ unit cost) and record it as an explicit assumption.2
TIMEOUTReport incumbent objective and MIP gap.Tighten the index set via limit, relax integrality where it is not semantically required, or accept the incumbent and say so.1

Elastic relaxation, concretely

For each elastic constraint, introduce slack s_c ≥ 0, rewrite g_c(x) ≤ b_c as g_c(x) ≤ b_c + s_c, and minimise Σ w_c · s_c. Every s_c > 0 in the solution names a rule that must bend and by how much. Hard constraints get no slack, so they are never quietly violated.

The demo moment — rehearse this exact wording "Your sustainability floor of 30 mpg conflicts with your $2M budget. They cannot both hold. The smallest change that makes this solvable is lowering the fleet target to 26.4 mpg — or, if the target is fixed, raising the budget to $2.31M. Every other rule you gave me is satisfied. Which would you like?"

Nobody demos this. Everybody demos a bar chart.

Failure taxonomy at the SDK layer A owns

Log run.id and agent.agent_id before you start streaming. If a stream hangs at hour twenty, those two IDs are the only way to find out what happened. 

try:
    run = agent.send(prompt, opts)
    log.info("run", run_id=run.id, agent_id=agent.agent_id)  # log BEFORE streaming
    result = run.wait()
    if result.status == "error":                     # executed, then failed -> repair
        return StageOutcome.retryable(result)
except CursorAgentError as err:                    # never started: auth/config/network
    if err.is_retryable:
        sleep(err.retry_after or backoff())
        return StageOutcome.retry_transport()
    raise

07Orchestrator skeleton

Enough to be a real starting point. Owner A should have this running against stub tools by H+5.

# orchestrator/pipeline.py
import os, json, pathlib
from cursor_sdk import (
    Agent, AgentOptions, LocalAgentOptions, SendOptions,
    CustomTool, CursorAgentError,
)
from orcore import tools as T

RUN_DIR = pathlib.Path("runs") / run_id
MODEL   = "composer-2.5"          # pinned. never "auto" during the demo.

def tool(fn, description, schema):
    return CustomTool(description=description, input_schema=schema, execute=fn)

OR_TOOLS = {
    "profile_dataset":       tool(T.profile_dataset,       T.D_PROFILE,   T.S_PROFILE),
    "validate_spec":         tool(T.validate_spec,         T.D_VALIDATE,  T.S_SPEC),
    "compile_and_solve":     tool(T.compile_and_solve,     T.D_SOLVE,     T.S_SOLVE),
    "diagnose_infeasibility":tool(T.diagnose_infeasibility,T.D_DIAGNOSE,  T.S_SPEC),
    "sensitivity_report":    tool(T.sensitivity_report,    T.D_SENS,      T.S_SENS),
    "run_scenario":          tool(T.run_scenario,          T.D_SCENARIO,  T.S_SCEN),
}

def run_pipeline(question: str, csv_path: str, bus):
    opts = AgentOptions(
        model=MODEL,
        api_key=os.environ["CURSOR_API_KEY"],     # explicit, not ambient
        name=f"lagrange-{run_id}",
        mode="plan",                               # formulate before acting
        disallowed_tools=["webSearch"],            # nothing to look up; saves latency
        local=LocalAgentOptions(
            cwd=str(RUN_DIR),                        # sandboxed per run
            custom_tools=OR_TOOLS,
            # setting_sources deliberately unset: inline config only
        ),
    )

    with Agent.create(opts) as agent:
        bus.emit("agent_created", agent_id=agent.agent_id)

        card = stage(agent, bus, "profile",   P.PROFILE.format(csv=csv_path))
        spec = stage(agent, bus, "formulate", P.FORMULATE.format(q=question, card=card))

        # plan -> agent mode once the human (or auto-accept) confirms the spec
        sol  = stage(agent, bus, "solve", P.SOLVE, mode="agent")

        attempts = 0
        while sol["status"] in REPAIRABLE and attempts < MAX_REPAIRS[sol["status"]]:
            attempts += 1
            bus.emit("repair_attempt", n=attempts, status=sol["status"])
            sol = stage(agent, bus, "repair", P.REPAIR[sol["status"]].format(**sol), mode="agent")

        brief = stage(agent, bus, "explain", P.EXPLAIN, mode="agent")

        usage = agent.get_usage()
        bus.emit("done", tokens=usage.usage.total_tokens,
                 cents=usage.cost.charged_cents if usage.cost else None)
        return brief

def stage(agent, bus, name, prompt, mode=None):
    opts = SendOptions(
        mode=mode,
        on_delta=lambda u: bus.delta(name, u),
        on_step =lambda s: bus.step(name, s),
    )
    run = agent.send(prompt, opts)
    bus.emit("stage_start", stage=name, run_id=run.id)
    result = run.wait()                                # ALWAYS
    if result.status != "finished":
        raise StageFailed(name, result.status, run.id)
    return read_artifact(RUN_DIR, name)              # stage writes JSON to the run dir

Custom tool definition B owns

# orcore/tools.py
D_DIAGNOSE = (
    "Explain WHY an optimization model is infeasible. Adds slack to every constraint "
    "marked elastic, minimizes total weighted slack, and returns the minimal set of "
    "business rules that must be relaxed and by exactly how much. Call this immediately "
    "whenever compile_and_solve returns INFEASIBLE. Never guess at a relaxation yourself."
)

def diagnose_infeasibility(args, context):
    spec = OptimizationSpec.model_validate(args["spec"])
    report = diagnose.elastic_relax(spec)
    return {
        "feasible_after_relaxation": report.solved,
        "violated_rules": [
            {"id": v.id, "source_phrase": v.source_phrase,
             "required_slack": v.slack, "human": v.sentence()}
            for v in report.violations
        ],
        "hard_conflicts": report.hard_conflicts,
    }
Tool descriptions are prompt engineering The description string is the only thing the model reads when deciding whether to call a tool. Spend real effort there. Note how D_DIAGNOSE states the trigger condition ("whenever compile_and_solve returns INFEASIBLE") and the anti-behaviour ("never guess at a relaxation yourself"). That one sentence is worth more than a page of system prompt.

08Three people, three workstreams

Split by architectural layer, not by feature, so the seams are few and typed. Each person owns a directory nobody else edits; cross-layer changes go through the frozen contract.

A  Agent Runtime — orchestrator/

The Cursor SDK specialist. Owns everything between the user's question and the tool belt.

Deliverables. Staged pipeline with per-stage toolset narrowing · version-controlled prompt files · the four-branch repair state machine · error taxonomy separating CursorAgentError from result.status == "error" · normalised event bus feeding the UI · replay.py for network-free playback · usage and cost telemetry · Agent.resume path for live Q&A.

Depends on. Tool signatures from B (stubs are fine from H+3) · event schema agreed with C.

Done when. A single command takes a question plus a CSV path and produces brief.md, with the full event stream on stdout, and survives an injected INFEASIBLE.

B  OR Core — orcore/

Deliverables. Depends on. Nothing. B can start at minute zero and should be furthest ahead by Gate 1.

Done when. pytest tests/golden is green for all three tracks and diagnose_infeasibility returns the correct violated rule for a deliberately over-constrained spec.

C  Product & Story — app/, deck, demo

The one who decides what the judges actually see. This role is undervalued and decides the winner.

Deliverables. Single-page UI: question box, CSV drop, live agent stream, traceability table, solution table, executive brief · the rule-to-equation traceability view (highest-value screen we have) · brief renderer with the "cost of each constraint" section · all four datasets downloaded locally · the wildcard dataset · the deck · the demo script and its timing · the recorded fallback video.

Depends on. Event schema and spec fixtures only. Builds against fixtures/ from H+1; never waits for a working pipeline.

Done when. The demo runs end to end in under six minutes, three times consecutively, on the presenting laptop.

Working agreements

  • Commit hourly, straight to main. No PRs, no branches. Broken main stops the line and everyone fixes it.
  • Fixtures are the contract. B commits a real schema_card.json and spec.json for Track A by H+2; A and C build against those files, not against each other's code.
  • Standup on the hour, ninety seconds. Shipped, next, blocked.
  • Blocked fifteen minutes is a team problem. Say it out loud. Nobody debugs alone for an hour in a hackathon.
  • C has veto over scope. If it will not be seen in the six-minute demo, it does not get built.

Fielding the three questions you will be asked

QuestionAnswer
"How do you know the model it wrote is correct?"Three layers: the spec is schema-validated and semantically linted before anything runs; every constraint traces to a source phrase a human can check in seconds; and the sensitivity report exposes which constraints actually bind, which is where a wrong model shows itself immediately. Plus golden tests with known optima on all three tracks.
"What happens on a problem class you did not anticipate?"The spec covers LP, MIP, assignment and scheduling shapes. Outside that, the escape hatch lets the agent emit a raw expression and the shell tool lets it write bespoke code — it degrades to a general coding agent rather than failing. Show the wildcard again if there is time.
"Is this just a wrapper around an LLM?"The LLM does translation. The mathematics is deterministic OR-Tools code we wrote, so the optimum is provably optimal, not generated. The interesting engineering is the repair loop — turning solver failure states into business language — and that is not a prompt, it is elastic relaxation.
